# PayFlow API integration

This project now exposes a server-side PayFlow API for ZippyGo and other merchants.

## Endpoint

`POST /api/v1/payment-links`

Authentication:

`Authorization: Bearer pf_test_...` or `Authorization: Bearer pf_live_...`

Example request:

```json
{
  "amount": 49.99,
  "currency": "GBP",
  "title": "ZippyGo Airport Transfer",
  "description": "Booking ZGO-ABC1234",
  "customer": {
    "name": "Jane Doe",
    "email": "jane@example.com",
    "phone": "447700900123"
  },
  "payment_methods": ["card", "bank_transfer", "wallet", "upi", "paypal"],
  "max_uses": 1,
  "return_url": "https://zippygotransfers.onrender.com/?payment_status=success&booking_ref=ZGO-ABC1234"
}
```

Response:

```json
{
  "success": true,
  "link_id": "pl_...",
  "checkout_url": "https://payflow-com.onrender.com/checkout/pl_..."
}
```

## Render environment

Set these on the PayFlow Render service:

- `SUPABASE_URL=https://lxbvechmapkaedahbwlv.supabase.co`
- `SUPABASE_SERVICE_ROLE_KEY=<your Supabase secret/service-role key>`
- `PAYFLOW_PUBLIC_URL=https://payflow-com.onrender.com`

**Never put `SUPABASE_SERVICE_ROLE_KEY` in the browser or in a `VITE_` variable.**

## Database

Run:

`supabase/migrations/20260809150000_add_payment_link_return_url.sql`

The PayFlow API uses the API key hash generated by the existing `create_api_key` function. The raw `pf_test_...`/`pf_live_...` secret is never logged or stored by the API. The API hashes the supplied key with SHA-256 and matches it against `api_keys.key_hash`.
